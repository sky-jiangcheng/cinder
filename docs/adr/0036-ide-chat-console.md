# ADR-0036: IDE 面板改成「对话台」——主体是对话流、项目锁定、历史折叠

状态：**Accepted（2026-11-02）**——由项目所有者拍定，参照 Cline 插件的界面标准重构两个 IDE 分发面
日期：2026-11-02
关联：[ADR-0009](0009-ide-presence.md)（VS Code 扩展）、[ADR-0027](0027-jetbrains-plugin.md)（JetBrains 插件，本 ADR **修订**其决策 2 的界面形态）、[ADR-0035](0035-jetbrains-mcp-primary-channel.md)（通道分层：八项数据能力走 MCP）、[ADR-0032](0032-approved-knowledge-page-visibility.md)（已批准知识页）、[ADR-0033](0033-evidence-ask.md)（证据问答 `repotory_ask`）、[ADR-0015](0015-human-gate.md)（人工闸门）
起始 schema：v28（**本 ADR 不改 schema**）

## 背景

两个 IDE 面板今天的形态是同一个：**搜索器**——一个输入框、一列缩略图、一个详情窗格。VS Code 侧是 `searchView.ts` 里那张 webview，JetBrains 侧是 `RepotoryToolWindow.kt` 里的 Swing 面板（ADR-0027 决策 2① 定下的「知识检索工具窗」）。

这个形态有三个结构性问题，都不是审美问题：

**一、主体不是对话，所以记忆读不成序列。** 一次查询的结果会覆盖上一次。Repotory 的定位是「AI 编程 Agent 的本地记忆层」——记忆的价值在**序列**里：一个 gotcha 是哪次排障的后续、那条决策是替哪次试验挡掉的。用户面对的却是一个永远只显示"最近一次检索结果"的窗口，**读不成一段历史**。而仓库里唯一能回答"这个问题"的东西——`repotory_ask`（ADR-0033，带 `Sources:` 的证据答案）——在 IDE 面板里**根本没接线**，面板只会 grep。

**二、作用域是全局的，而用户问的几乎都是本项目的事。** 面板检索整个知识库（33 个项目 / 143 仓库量级），结果里混着别的项目的同类词。用户在自己的工作区里问「这个项目为什么重试 503」，面板却给他全库的 503 片段，且**说不出这些片段来自哪个项目**。桌面端的项目页是按项目切的，IDE 面板不是——两个面对同一份数据给出两种范围。

**三、历史不折叠。** 一屏放不下时就只能滚动或者关掉重来，没有"把旧的折起来"这个动作。Cline 对同一个问题的答案是：**推理块默认折叠、任务历史独立于正文**。

参照对象是 **Cline**（VS Code 上的 agent 插件）：它的 `ChatView` 以**对话流**为主体，底部是**常驻输入区**（自动增高、@ 提及、斜杠命令），顶部是**公告条**（状态与公告，不是状态行），侧栏/Tab 两套布局分别取紧凑与展开形态，历史浏览器与正文分离。

## 决策

### 决策 1：主体是对话流（conversation feed）

面板的主区域是一段**可追加的对话**：一问一答是一轮，轮与轮之间不覆盖。旧的轮留在流里（按决策 3 折叠），读者能看见"我问过什么、它答了什么、依据是哪几条"。

对话流是**唯一的滚动区**。详情不再有独立的窗格——点开一条笔记/一页知识，它的正文**就地展开成卡片**（Cline 的展开卡片形态），卡片上带编辑 / 复制 / 在 Repotory 中打开三个动作。

### 决策 2：项目锁定为当前项目

面板的作用域**默认锁定在当前工作区所属的项目**，锁在输入区的 chip 上显示（项目名 · 🔒）。这是默认值而不是限制：chip 可以点开解除锁定，解除后回到跨项目。

三种模式里，**两种由服务端真的过滤**：

- **Ask**：`repotory_ask` 传 `project_id`（`AskAIWithEvidence` 按项目取证）；
- **Pages**：`repotory_wiki_search` 传 `project_id`（项目页 + 全局页，ADR-0031）；
- **Notes**：`repotory_notes_search` 的工具面**没有项目过滤参数**（`path` 只影响排序，不过滤），所以锁定在插件侧按 `project_id` 过滤命中项——**这是一次呈现层过滤，检索与排序仍由服务端算**，插件不复制检索逻辑（薄客户端纪律不变）。

### 决策 3：历史折叠

- **轮次折叠**：超过最近 **2 轮**的旧对话折成一行「N 轮更早的对话 ▾」，点开再展开。这是 Cline 的折叠推理块用在**轮**上的形态。
- **证据折叠**：每个答案的来源清单默认折叠成一行「来源（N）」，点开才列出条目——答案本身才是主体，证据是它的注脚。
- **折叠状态是显式的**：被折叠的轮次在会话内保持折叠（不随重渲染复位）——Cline 面板的一个已知痛点正是"折叠开关每次关面板就复位"。

### 决策 4：三种模式

模式是输入区上的一排切换（Cline 的 mode 切换位），对应三个知识面：

| 模式 | 工具 | 产出 |
|---|---|---|
| **Ask**（默认） | `repotory_ask` | 带 `Sources:` 的答案 + 可展开的来源清单 |
| **Notes** | `repotory_notes_search` | 命中的卡片（笔记 / 待办） |
| **Pages** | `repotory_wiki_search` | 已批准知识页的卡片 |

Ask 排在默认位，是因为**它是唯一产出"答案"而不是"命中"的面**，也是 ADR-0033 已经造好的那条能力。

### 决策 5：公告条取代状态行

状态与错误从面板底部那条状态行，移到对话流顶部的**公告条**（Cline 的 Announcement Bar）：一行、有底色、错了能看见、可以点掉。面板底部让给输入区。

### 决策 6：输入区常驻底部

多行输入框（随内容增高）、模式切换、作用域 chip、发送按钮，一行排布。它**常驻**——不像今天那样"输入框在上、结果在下、详情再在下"三层纵向切分。

### 决策 7：不再有独立的详情窗格

今天的"缩略图列表 + 详情窗格"整体取消。理由是决策 1 的推论：主区域只能有一个滚动区，否则窄侧栏里两栏会把详情挤成几列读不出来的字（ADR-0027 记过这个坑：侧栏窄而高，左右分栏在那个形状里把详情挤成几列）。

### 决策 8：两个 IDE 同构

VS Code 与 JetBrains 的面板**同一套结构、同一套措辞、同一套折叠规则**（ADR-0035 决策 2 已经把两个分发面拉成同构，这里是它的延伸）。两个分发面各自实现，但**看得见的部分必须一致**——差异只允许存在于"怎么把 Swing 画成 HTML"这一层。

## 后果

- **正面**：面板第一次能回答问题（`repotory_ask` 接线），而不只是检索；作用域与桌面端的项目页对齐；旧对话折叠起来后，长会话里"我刚才问过什么"随时可查可展；两个 IDE 的观感一致。
- **负面（面板变重）**：对话流与输入区是新的前端结构，两个分发面都要重写面板（VS Code 侧重写 `searchView.ts` 的 webview 与消息协议，JetBrains 侧重写 `RepotoryToolWindow.kt` 的面板）。检索、解析、传输层**不动**——ADR-0035 的通道分层不受影响，八项 MCP 工具照旧。
- **负面（工具面未扩）**：`repotory_ask` 的答案是**文本**，来源清单要从文本里解析（`[P1] note "标题" (id 42, project X)`）。这是文本契约的脆弱处：解析失败必须**降级成原样显示整段文本**，不能吞掉来源。
- **负面（Notes 模式的锁定是呈现层过滤）**：全局检索的前 N 条里若大部分属于别的项目，本项目的结果会少于 N 条。这是"锁定"的诚实代价，界面必须说明范围，而不是假装命中数就是全部。
- **中性**：命令面板的既有命令保留（`Repotory: Search Knowledge` 等），改为**往对话流里追加一轮**而不是替换结果；设置页、搜索范围解析、MCP 二进制查找等**均不受本 ADR 影响**。
- **不变**：薄客户端纪律（插件不复制检索逻辑）、人工闸门（机器写的措辞仍要人审）、冻结标识、schema。

## 落地清单

1. `ide/vscode/src/searchView.ts`：webview 重写为对话流 + 输入区 + 公告条 + 折叠；消息协议扩展（`ask` / `turn` / `announce` / 折叠状态）。
2. `ide/vscode/src/extension.ts`：`repotory_ask` 接线、作用域解析（工作区 → 项目）、来源解析、命令改为追加一轮。
3. `ide/jetbrains/`：面板重写为同构形态（Swing：对话流用 HTML 渲染 + 底部输入区 + 顶部公告条）。
4. 两个分发面的文案、折叠规则、模式语义逐条对齐。
5. 手册与两个 README 同步（面板形态变了）。

## 落地记录（2026-11-02）

清单已全部落地，但**第 1 条的文件落点与原文写的不一样**——原文写的是「重写 `searchView.ts`」，实际是**删掉那个文件、把一个 webview 拆成四个模块**。原因：旧 `searchView.ts` 把 webview 的 HTML、消息协议与业务逻辑揉在一个文件里，重写成对话流时既要改 UI 又要改协议，拆开才能让协议层与会话层有单测可碰（`chatConsoleHtml.ts` 是整个扩展里唯一没有单测能碰到的代码，故单独成文件且不 import `vscode`）。

- **VS Code 侧**：`ide/vscode/src/` 从 4 个文件变 6 个——`chatTypes.ts`（协议类型：webview↔host 全部消息，**两侧 import 同一份**）、`chatConsoleHtml.ts`（面板 markup/CSS/JS，**不 import `vscode`**）、`chatConsole.ts`（webview provider）、`chatSession.ts`（对话模型 + `Transport` 端口），`searchView.ts` 删除。`extension.ts` 接线 `repotory_ask`、项目锁定、Notes 呈现层过滤、命令改追加轮；新增命令 `repotory.ask`。
- **JetBrains 侧**：新增四个**纯 JVM、无 IntelliJ 依赖**的文件（所以能脱离 IDE 单测）——`ChatModel.kt`、`ChatSession.kt`、`ChatConsoleHtml.kt`、`McpChatTransport.kt`；`RepotoryToolWindow.kt` 面板主体重写（1372 → 1245 行）；`RepotoryMcp.kt` 新增 `callToolText`（对话台要读 `repotory_ask` 的**原文**来解析来源）。
- **两端同构的落地方式**：同一套措辞、同一套折叠规则（最近 2 轮可见 + 「N earlier turns ▾」+ 「Sources (N)」）、同一套过滤说明（`Locked to <项目>: K of N matches shown.`）。差异只允许存在于「怎么把 Swing 画成 HTML」这一层。
- **同批修掉的三个真 bug**（两端互相挑出来的，各有回归测试钉住）：① VS Code 侧空答案措辞被自身覆盖（赋值顺序错）；② 卡片寻址只按 id（笔记与待办是独立 id 空间，会打开错项）→ 改 type+id；③ 待办卡片拿 id 去 `notes_read` 读到同号笔记 → 改为直接给摘录不发调用。
- **顺带修掉的构建缺陷**：`build.gradle.kts` 里 `buildSearchableOptions { enabled = false }` 不够——`prepareJarSearchableOptions` 的输入目录不存在，Gradle 拒绝执行，**干净树 `gradle buildPlugin` 直接红**（CI 门禁同样红）。必须把整条链关掉。
