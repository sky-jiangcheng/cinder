# ADR-0037: 品牌辨识度的三层收口——把「印出来的卡」从图标扩展成界面语法

状态：**Accepted（2026-11-02）**
日期：2026-11-02
关联：[ADR-0034](0034-desktop-three-column-shell.md)（桌面外壳三栏化，品牌标记留在左栏）、[ADR-0021](0021-*.md)（若有则并入）、[ADR-0036](0036-ide-chat-console.md)（两个 IDE 面板改成对话台）、[ADR-0006](0006-scope-reduction.md)（范围冻结）、[ADR-0007](0007-session-memory-protocol.md)（会话记忆协议）
起始 schema：v28（**本 ADR 不改 schema**）

## 背景

用户指出：**「辨识度不高」**，并补了一句约束——**「不能强行提高知名度，那样会导致后续难改」**。

这两句放在一起，定的是方向而不是力度。要提高辨识度，常规做法是换一个更花哨、更独特的符号、更强的对比色，做一个「让人一眼记住」的东西。但那正是用户明确不要的：**知名度一旦靠某个具体形状建立起来，那个形状就成了负债**——将来想改（换字体、改色彩、改形状），第一件事就是「会不会掉粉」。

所以本 ADR 要的不是「更强的符号」，而是**一个能持续承载识别、且允许逐代替换的结构**。这要求先诊断清楚：辨识度低，**低在哪一层**。

### 诊断：三层不同步

**第一层 —— 母图（`build/icon.svg`，v4 产物）**

现行母图是「奶油卡 + hairline 框 + 粗体 R」：暖纸底 `#F5F0E4`、近黑墨 `#1B1B1B`、9 单位 hairline 框（512 网格，内缩 26）、IBM Plex Sans Bold 的 R（320 单位 cap height，因 R 重心偏左而右移 6 上移 2）。

母图本身是**好的**——「印出来的卡」这个概念成立，方边与 hairline 的关系讲得清楚，三域规则（品牌域 / OS 应用域 / 字形域）已经把「同一字母、三种容器」这件事工程化了。

问题在**承载识别的元素选错了**：「R」是全世界最通用的一个字母，替换成任何其他字体都还是「一个方框里一个字母」。真正让这张卡区别于「随便一个 App 图标」的是**那圈 hairline 框**——但框目前是**装饰**（一圈描边），不是**语义**（一个可被复述的构造规则）。**换掉字体，整个品牌就塌了**，说明品牌没有落在可迁移的构造上。

**第二层 —— 色彩（UI token）**

母图是暖奶油 + 近黑。但 UI 的 token 是另一套语言：

```
--bg-primary: #f5f5f3   --accent: #2563eb (Tailwind blue-600)
--bg-secondary: #ffffff --accent-soft: #eff6ff
```

量一下：`#F5F0E4`（品牌奶油）在**整个 web/src 里只出现在 `BrandMark.tsx` 一个组件**——UI 的其余部分没有一个像素用它。界面的观感是「一个中性的、偏蓝的软件」。

这就是用户看到的割裂：**蓝色界面里贴了一张奶油色图标**。图标和界面不像一个产品。

**第三层 —— 尺度（UI 里的标记）**

`BrandMark` 在桌面左栏以 26px 渲染。母图那圈 hairline 是 **9/512 单位**——到 26px 只剩 **0.46px**，不到一个像素，浏览器会把它渲染成一条糊掉的灰线。

于是 UI 里的品牌标记实际观感是：**「一个几乎看不见边框的 R」**。和普通文字、和其他产品的单色字形**没有可区分的特征**。这就是「辨识度不高」最直接的来源——**标记在最需要被认出来的地方，恰好失去了它唯一的识别特征**。

> 这里有一条已被仓库记录的教训：`CONTRIBUTING.md`「品牌图标三域规则」写着「小尺寸要重新配重——母图 hairline 在 512 网格上是 9 单位，到 24px 只剩 0.42px（不足一个像素，糊成一条灰线）」。**字形域已经按 34 单位（24px 下 1.6px）重新配重了，但 UI 里的 `BrandMark` 没有**——它直接照抄母图几何，等于把刚解决过的问题留在了应用界面上。

### 为什么不能靠「加大标识」解决

把 26px 改成 48px、加个渐变、加个彩色底、换个更罕见的字母——这些都能立刻提高一眼认出的概率，但每一项都在制造上面说的负债：

- **加渐变**：渐变是强视觉特征，也是强锁定项。母图现在明确写着「No gradient, no shadow, no rounded corners — the square edge and the hairline are the style」。加渐变等于把这条风格声明作废，且将来要撤。
- **换罕见字母**：辨识度会跳升，但品牌从此绑死在一个字形上，且「罕见」本身不传达任何关于产品是什么的信息。
- **加大尺寸**：占用本就不宽的左栏（ADR-0034 定的 72px），且不改变「特征不可见」这个根本问题。

## 决策

### 决策 1：辨识度靠「构造」不靠「符号」——把 hairline 框提升为品牌语义

品牌标记的识别点**从「字母 R」迁移到「印出来的卡」这个构造**：

> **一张方形暖纸卡，边上有一圈比正文更重的墨线，纸上有一个近黑的字。**

这个构造有三个好处：

1. **可迁移**：换字体、换字母、换纸张色，识别点仍在。反过来，若识别点押在字母上，换字体即失去识别。
2. **可复述**：用户能说出「那个米色带黑框的方块」——描述的是构造，不是字形。
3. **可延展**：这个构造天然能扩展到界面元素上（决策 2），而不只是图标。

**字母降级为「占位」**：R 仍是 R（不换，避免无谓的破除），但它不再承担识别责任。**品牌识别由构造承担，字母是变量。**

> 这一点是对 v4 的**修订而非否定**：v4 立的「母图单一事实源 + 三域派生」纪律完全保留，本决策加的是**识别点的重新指定**与**UI 侧的对齐**。

### 决策 2：把「印出来的卡」变成界面语法——品牌色进入 UI token

UI 不再是「中性灰 + Tailwind 蓝」，而是**从母图取色**：

- **暖纸底**：页面底色从 `#f5f5f3` 转向母图奶油 `#F5F0E4` 家族；卡片面取比底色更亮一档的纸白，而不是纯白 `#ffffff`（纯白是屏幕白，与暖纸底并置时会显脏）。
- **墨色**：正文墨色从 `#1a1a1a` 转向母图墨色 `#1B1B1B` 家族，与标记同源。
- **强调色**：**弃用 Tailwind 蓝**。新的强调色取自母图的**墨色 + 暖色偏移**——一条深暖褐／墨色的强调线，而不是冷蓝。

**理由**：品牌色一进界面，识别就不再依赖「用户记得那个图标」，而依赖**整个产品的观感一致**。这比任何符号都更稳，也更可持续——将来换色、换字体、换整个母图，界面跟着换即可，不存在「老用户只认得旧图标」的问题。

**约束**：强调色必须仍满足 WCAG AA（对底色 ≥ 4.5:1），深色主题同样。**这不是审美偏好，是硬门**——`semanticInk.test.ts` 已有的语义色不变量继续适用。

### 决策 3：UI 里的标记按小尺寸重新配重（补上字形域的同一条规则）

`BrandMark` 在 UI 尺寸下**不复用母图的 9 单位 hairline**，改用**随渲染尺寸缩放的线宽**：

- 26px 下线宽落到**至少 1 物理像素**（20 单位的等效值），保证「框」这个识别特征真的可见；
- **框随之内移**，以保住**至少 1 物理像素的纸边**——线宽变粗后若仍按母图的内缩 26 单位画，框会把卡片边缘吃掉，标记会读成一个「深色方块」而不是「印出来的卡」；
- **≤16px 退化为纯字形**（单色、取 `currentColor`，于是它属于所在表面而不是固定近黑）——和仓库既有的「字形域」规则一致（16px 只放字母、不放框，13px 的奶油卡在深色侧栏里是一块发亮的方块）；
- **512px 仍是母图本身**（9 单位线宽、内缩 26）——配重不得向上蔓延。

**理由**：决策 1 说识别点是「框」，那么框在**实际会被看见的尺寸**上就必须看得见。母图 9 单位是给 512px 网格的印刷／大尺寸场景调的，直接缩到 26px 必然失效——这是已被记录过一次、却漏改了 UI 侧的同一个错误。而「框 + 纸边」是一对：**只有框没有纸边，框就退化成一道普通描边**。

### 决策 4：不引入新符号、不动三域结构、不改品牌名

- **不换字母、不换构图、不加渐变／阴影／圆角**：见「为什么不能靠加大标识解决」。
- **三域规则（品牌域 / OS 应用域 / 字形域）不变**：本 ADR 只改**UI 侧的对齐**与**识别点的指定**，母图本身的几何不动（hairline 9 单位在 512 网格上是对的）。
- **品牌名 `Repotory` 不动**：冻结标识（ADR-0006）。「辨识度」问题在**视觉构造**上，不在名字上。
- **不新增 MCP 工具、不改 schema、不新增绑定**：纯视觉层。

### 决策 5：识别点必须被断言钉住，否则会被改回去

品牌纪律靠 CI 兜底，不靠记性。本 ADR 落码时补：

1. **`BrandMark` 的 hairline 随尺寸配重**：测试断言「在 UI 实际使用的尺寸下，框的渲染宽度 ≥ 1px」（不是断言某个魔数——断言**性质**）。
2. **品牌色确实进了 token**：测试断言 `--accent` 不再是那支 Tailwind 蓝，且 token 里的品牌色与 `build/icon.svg` 里的取色**同源**（从母图读值比对，防止两边漂移）。
3. **`semanticInk.test.ts` 的不变量继续覆盖新的强调色**：102 处 `var(--accent)` 用量下，语义色被静默压平的风险与之前一样。

> 教训来源：`CONTRIBUTING.md` 记着「本品牌历史上四次半落地（活动栏/工具窗/favicon/README 各漏一次改版）根因全部是手养副本」。**这次的对应风险是「UI 与母图再次分家」**——所以断言必须读**母图**作为事实源，而不是把色值抄进测试。

## 后果

- **正面**：辨识度从「靠用户记住那个图标」变成「整个产品的观感一致 + 标记在任何尺寸下都保留识别特征」；且**不制造新的锁定**——将来换母图，界面跟着换即可，不需要担心老用户只认旧符号。
- **正面（对 IDE 面）**：ADR-0036 的两个 IDE 面板已有品牌标记（VS Code 活动栏 / JetBrains 工具窗），本 ADR 的「暖纸 + 墨」语义与它们同源，三个分发面第一次说同一种视觉语言。
- **负面（改动面不小）**：`--accent` 有 **102 处**使用，改色会波及整个桌面端界面；需要逐屏核对，不能只看首页。
- **负面（对比度需重新配平）**：从冷蓝换成暖墨后，所有 `--accent` 承载的文本/图标都要重新核对 AA 对比度；深色主题同理。
- **中性**：不改 schema、不新增工具、不新增绑定、不改品牌名、不动母图几何。
- **中性（与 ADR-0036 的关系）**：ADR-0036 定的是**面板的结构与交互**（对话流、项目锁定、历史折叠）；本 ADR 定的是**品牌标识与界面语法**。两者正交，不冲突。

## 落地记录（2026-11-02）

**逐对 AA 审计全绿。** 全部 token 对（正文三级墨色 / 强调色 / 语义色 / 控件边框 / 品牌两色）× 全部表面（`--bg-primary` / `--bg-secondary` / `--bg-tertiary` / `--bg-hover` / `--bg-active` / `--accent-soft` / 各 `-soft`）在**浅色与深色两套主题**下逐对比过，旧调色板里所有不达标的配对本次**全部达标**：

| 配对 | 旧（浅色） | 新（浅色） | 旧（深色） | 新（深色） |
|---|---|---|---|---|
| `--accent` on `--bg-tertiary` | 4.38 ✗ | 6.50 | 5.65 | 6.05 |
| 纸白 on `--accent-light`（主按钮 hover 态） | 3.68 ✗ | 6.14 | 8.82 | 9.03 |
| `--warning` on `--bg-primary` | 4.34 ✗ | 5.69 | 8.82 | 10.21 |
| `--warning` on `--bg-tertiary` | 4.02 ✗ | 5.29 | 7.28 | 8.69 |
| `--text-tertiary` on `--bg-active` | 4.22 ✗ | 4.58 | 4.04 ✗ | 4.59 |
| `--danger` on `--bg-active` | 5.16 | 4.83 | 3.88 ✗ | 4.59 |
| `--info` on `--bg-active` | 4.35 ✗ | 4.58 | 4.17 ✗ | 4.71 |
| `--border-default` on `--bg-primary` | 1.52 ✗ | **3.25** | 1.53 ✗ | **3.65** |

`--border-default` 是控件边界（按钮、输入框、chip），适用 WCAG 1.4.11 的 3:1 非文本对比度——旧值 **1.52:1** 是一笔**既有欠债**，本 ADR 顺带还清，不算新增要求。

**标记实测**（2 倍像素密度逐像素核对）：26px 从「一条被糊开的灰线」变成「实心墨框 + 可见纸边」；22 / 20 / 17px 同样保住 ≥1px 的框与 ≥1px 的纸边；16px 退化为单色字母。

**同源断言**已建立：`web/src/styles/brandTokens.test.ts` **从 `build/icon.svg` 读值**比对 `--brand-paper` / `--brand-ink`，并断言两个主题的主墨色恰好是母图两色的互换；`BrandMark.test.tsx` 断言的是框宽与纸边的**性质**（≥1px）而非某个魔数。强调色与正文墨色的 AA 由同一文件**按属性**校验——调色板可以重调，掉到不达标则测试会红。

**IDE 面核对结论**：两个 IDE 面的品牌标记**本来就符合**本 ADR 的语义——VS Code 活动栏 24px 是「字形域 + 34 单位墨框」（1.6px），JetBrains 工具窗 16px 是「纯字母单色」，正是决策 3 定下的两档；母图未动，`scripts/generate-icons.mjs --check` 同步门**无需改动即通过**。UI 侧此前是**唯一**没有配重的那一面。

**第四个面：文档站。** 核对时发现**文档站原本在说第三种颜色语言**——应用是「中性灰 + Tailwind 蓝」，图标是「暖纸 + 近黑」，而文档站的主题 accent 是 **Material Green 500（`#4caf50`）**，一个与产品里任何东西都没有关系的遗留色。**这才是「辨识度不高」在生态级的根因**：不是某一个图标不够好看，是三个门面各说各话。已把文档站 accent 收到品牌色家族：内容区用暖墨 `#7A3E12`（与应用的浅色主题同一个值），深色侧栏用暖琥珀 `#E09155`（与应用深色主题同一个值——深墨在深底上读不出来），提示框的蓝底改为品牌 `--accent-soft` 暖纸底。**顺带还清一笔既有 AA 欠债**：旧绿在文档站浅底上只有 **2.64:1**（链接文字不达标），新暖墨 **7.89:1**；深色侧栏上的琥珀 **6.78:1**。**三处有意不动**：① 文档站的中性色（浅灰底 / 石板字 / 深藏青侧栏）**保持原样**——那是文档站自己的结构配色，不是品牌色，把它们一并换掉是一次设计工程，不是品牌识别修复；② 首页架构图那四个节点色（人 / Agent / 核心 / 初始化）是**图例语义**，四个层要能互相区分，统一成暖色系会把图例抹平；③ 文档站的品牌标记**不重新配重**——它 28px 落在**深色**侧栏上，奶油卡与深底高对比、卡片本身就是识别特征，母图几何直接内联即可（这也是 JetBrains 字形域那条教训的适用边界：**深底上卡片反而更清楚，问题出在浅底上卡片与底色融掉**）。

**落地清单逐项**：1–4 已完成（token / 组件 / 两处断言）；5 本 ADR 双份 + 索引已更；6 见 `CHANGELOG.md` 与 `TODO.md`；7 核对结论如上，**IDE 侧无需改动**；**另补文档站第四面（accent 对齐 + AA 修复）**。

## 落地记录（2026-11-02，续）：界面内最后几处手养旧配色

上一节收的是「**门面**」（应用 / 文档站 / 两个 IDE 面）。这一轮查的是**界面内部自己**：凡是没有走 token、手写死颜色值的地方，都各自存了一份旧调色板——它们与母图无关，也与新 token 无关，只是「当时是那样写的」。

| 位置 | 旧值 | 现在 |
|---|---|---|
| 外观页的主题缩略图（`AppearanceTab.module.css`） | 中性灰纸面 + Tailwind 蓝强调线 | 该主题**真实**配色的微缩版（暖纸 + 暖墨线 / 暖黑 + 琥珀线） |
| 仪表盘活动热力图（`Heatmap.module.css`） | 冷中性灰五阶 + 一份深色主题覆盖 | 由 `--text-primary` 与 `--bg-secondary` 派生的五阶，深色主题自动反相（覆盖行整段删除） |
| 深色主题的 note 引用块（`features/markdown.css`） | 蓝色 rgba 底 | 由 `--accent` 派生的暖琥珀底 |
| 代码块（`design-system/typography.css`） | 冷灰近黑 + 冷灰字 | 浅色=品牌墨底 + 品牌纸字，深色=暖底 + 暖字阶 |
| `BlockEditor` 的 `--accent` 兜底值 | 蓝 | 暖墨 |
| `index.html` 的 `theme-color` | 冷近黑 | 浅/深两套 `prefers-color-scheme` 下的暖纸 / 暖黑 |

**缩略图是这次最要紧的一处。** 那三个 64×44 的小方块**声称**是「该主题下这个 app 的微缩版」（源码注释原话）。换色之前它画的是中性灰 + 蓝——**它在对用户说谎**，说的还是这个产品已经不用的那种语言。现在它画的是真实配色，而且**不能靠读实况 token**：缩略图必须能画出「当前没启用」的那个主题，所以两套配色的目录值被显式列在 `tokens.css`（`--preview-light-*` / `--preview-dark-*`），再由断言钉住「目录值 == 它所描绘的实况 token」——**目录一旦漂移，测试就红**。

**新增两道断言**（`web/src/styles/brandTokens.test.ts`）：

1. **预览目录必须等于实况配色**：逐条比对（`--preview-light-accent` == 浅色 `--accent`、`--preview-dark-page` == 深色 `--bg-primary` ……）共 10 条；且目录**只在 `:root` 声明一次**（深色主题不得重声明，否则就有第二份可漂移的副本）。
2. **旧调色板不得回流**：把 ADR-0037 换掉的每一支旧色（Tailwind 蓝一族、冷灰一族、那支蓝色 rgba）列成清单，扫 `web/src/**` 与 `web/index.html`，**命中即红**。这条防线连注释一起扫——它确实抓到了本轮自己写进注释里的两个旧色号。

> 教训：**换色从来不是「改一个 token」就完**。凡是手写颜色值的地方都各自存了一份调色板，换色只改得到走 token 的那一半；另一半要靠「把所有手写色值扫出来逐个归位」才收得干净。这次若只做 token 替换，界面上仍会挂着四处旧语言（外观页缩略图、热力图、引用块、代码块），而每一处单看都「没什么问题」。
