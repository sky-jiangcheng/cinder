# ADR-0039: 页面内的平铺区块收成 tab——一次只看一个

- 状态：Accepted（2026-11-02，用户指出「仪表盘、知识库、审核多处可以用 tab 但是没有使用」）
- 日期：2026-11-02
- 关联：[ADR-0038](0038-desktop-information-architecture.md)（**本文不翻转它的任何决策**，只把它的落地粒度从「区块」细到「tab」）、[ADR-0032](0032-approved-knowledge-page-visibility.md)（只列已批准页的语义不变）、[ADR-0019](0019-entity-disambiguation-merge.md)、[ADR-0020](0020-community-summary.md)、[ADR-0023](0023-knowledge-import-landing.md)、[ADR-0017](0017-one-kernel-two-entry-points.md)

## 背景

ADR-0038 把顶级入口从 7 收到 5，做的是「同一动作一个入口」这一层。**页面内部**还有同一类毛病没治：三个页面各自把若干**互不相干的同级区块**平铺在一个长滚动里，用户要滚过不相干的内容才能到达目标区块。

逐条核对代码后的实况：

| 页面 | 平铺的同级区块 | 问题 |
|---|---|---|
| 审核 | 待审核队列 / 合并候选 / 页面作用域 / 编译任务 / 已否决 / 社区摘要报告 | **六块平铺，每次只用一块**；合并候选最多 20 行，审队列在它前面 |
| 知识（笔记视图） | 笔记网格 / 待整理（知识库整理） | 「待整理」在**约 10,000px 页面**的最底部，只能靠一个「待整理 14」跳转按钮找到 |
| 仪表盘 | 记忆环（会话）/ 关注的项目 / 其他项目 | 「上次的会话」与「我的产出」两种不相干的对象平级堆叠 |

**而 tab 就在隔壁**：项目页（`/project/:id?tab=notes`）、设置页、快捷录入 FAB 都已经是 `role="tablist"` + 方向键漫游焦点的真 tab。审核、知识、仪表盘三个页面**一次都没用**，而是继续用「小标题 + 区块堆叠」的手写结构——于是同一个产品里有两种切换语言的写法。

而且这一篇的毛病**不是审美**：

- 审核页的六块内容形状完全不同（一个审批队列 / 一张候选对列表 / 一张作用域表 / 一个任务列表 / 一份否决记录 / 一张统计报告），动作也完全不同（批准、合并、提升、指派、取消、删除）。它们**不是一份列表的筛法**，是六个地方。
- 知识页的「待整理」是**另一个工作台**（把落位桶里的笔记归口到真实项目），不是笔记的一个筛选子集。代码里那个「待整理 14」跳转按钮就是证据——一个控件的存在本身说明「它在别处，而且不好找」。
- 仪表盘的「记忆环」讲的是**上次的会话**，「项目列表」讲的是**今天的产出**。ADR-0038 决策 5 把记忆环搬进仪表盘的理由是「它属于『我的状态』」，却没给它一个独立的容器——于是两种不相干的对象又一次平级堆叠，**正是 ADR-0038 要消灭的那个形状换了个位置复现**。

根子上和 ADR-0038 是同一件事：**把「一次只需要看一个」的东西并排放着，让人自己滚**。ADR-0038 治的是顶级入口之间，这一篇治的是页面内部的区块之间。

## 决策

### 1. 三分法：什么该是 tab，什么该是 chip，什么该是分段控件

| 形状 | 语义 | 判据 | 例子 |
|---|---|---|---|
| **tab** | **一次只需要看一个的同级区块** | 内容不同、形状不同、动作不同 | 审核页的五个队列；仪表盘的「项目 / 会话」 |
| **chip / filter** | **同一列表的筛法** | 同一批数据、不同子集 | 知识页的标签 / 主题 / 全部-知识-其他；仪表盘的「全部 / 关注」 |
| **分段控件** | **同一对象的两态** | 同一份内容、两种面貌 | 知识页的「笔记 / 知识页」（ADR-0038 决策 4，**不变**） |

这条线在 ADR-0038 里已经画过一次（「同一对象两态用分段控件」），本篇把它补全成三分法。**照此执行，不再出现第四种说法**——过去三个页面各写各的，正是因为缺这条线。

### 2. 审核页：五个队列 = 五个 tab

`待审核`（默认）/ `合并候选` / `页面作用域` / `任务` / `已否决`。

- **每个 tab 带计数徽标**——数量是判断「该不该点进去」的依据，不带计数的 tab 逼着用户逐个点。
- **空 tab 不占位**：「页面作用域 / 任务 / 已否决」只在有内容时出现。现状已经是「没有就不渲染」，本决策把它从「区块」改成「tab」，语义不变。
- **「待审核」与「合并候选」始终出现**：前者是主队列（空时给空态），后者「什么都没找到」本身就是审核员要的答案（ADR-0019 的结构扫描）。
- **「任务」tab 里同时放编译 / 校验任务列表与社区摘要报告**：两者都是「机器跑出来的结果」，不是队列。
- 切换 tab 后内容区回到顶部——否则停在旧区块的中段，切换像是没生效。

### 3. 知识页：「待整理」从页面底部提到笔记视图的 tab

- 笔记视图内加一组 tab：**「全部笔记」/「待整理（N）」**。
- **「待整理 N」跳转按钮删除**——它是为「东西藏在页面底部」发明的补丁，tab 一旦存在，这个补丁就没有存在理由了。
- 「待整理」tab **只在有待整理笔记时出现**（待整理数为 0 时不占位），与现状「没有就不渲染」一致。
- 顶层「笔记 / 知识页」分段控件**不变**（ADR-0038 决策 4）。两层控件各司其职：外层分段控件是「知识库的两个抽屉」，内层 tab 是「笔记抽屉里的两个视图」；两者的形状与位置都不同，不会混淆。

### 4. 仪表盘：「项目 / 会话」两个 tab

- **「项目」（默认）**：现有的关注的项目 + 其他项目两个 section。**这两块是同一批数据的两个分段，是 chip 语义不是 tab 语义**——「全部 / 关注」那个范围开关和 summary 的口径都**不动**。
- **「会话」**：记忆环（最近交接记录 + 写一条交接记录）。
- 「会话」tab **带交接记录条数徽标**——ADR-0038 决策 5 要的是「首屏可达」，tab 栏本身就在首屏，徽标让「有 3 条没看」一眼可见；把它埋进 tab 而不加徽标才是把 ADR-0038 的落点改弱了。

### 5. 一处权威的 tab 实现

- 抽出 `web/src/components/TabStrip.tsx`：`role="tablist"`、`role="tab"`、`aria-selected`、`aria-controls`、方向键 / Home / End 漫游焦点、计数徽标。
- 样式沿用设计系统已有的全局 `.tab-btn` / `.tab-active`，**不新造第二套**。
- 三个页面共用这一个组件。设置页与项目页**暂不迁移**（它们已有各自的 tab 实现，迁移是另一件事，不在本篇范围）——但新代码不再另写第三种。

### 6. 可寻址性：三个页面的 tab 都进 URL

- `/review?view=pending|merge|scope|jobs|rejected`
- `/knowledge?view=notes|pages&sub=organize`
- `/dashboard?view=projects|sessions`

判据与 ADR-0038 落地时修好的那套**完全一致**：只有 `useNavigationType() === 'POP'`（后退 / 前进）才算外部改动，自己的写入走 `written` ref 记账——react-router 的 `setSearchParams` 走 transition，中间有一帧 URL 仍持有旧值，把那一帧当成外部改动就会把用户刚填的内容吃掉。

### 7. 不动的东西

不改后端、不改 schema、不改数据口径（仪表盘的「全部 / 关注」范围开关与 summary 的聚合口径**一字不动**）；不动审核的批次语义（pending / rejected / approved 三个集合照旧各自取数）；不动项目页与设置页的 tab；不改 ADR-0038 的任何决策；不动知识页的只读语义（ADR-0032 决策 1 仍成立）。

## 后果

- **正面**：三个页面从「滚过不相干的内容才能到达目标」变成「一次只看一个」；审核页从六块平铺变成五个带计数的队列，**要哪一块点哪一块**；「待整理」从 10,000px 底部提到一级 tab，那个跳转按钮得以删除；仪表盘的「会话」与「项目」不再混在一页。
- **正面（一处权威）**：tab 只有一套实现、一种无障碍语义、一种键盘操作方式；项目页、设置页已有的 tab 与新加的这三处说同一种语言。
- **负面（内容默认不可见）**：tab 化的直接代价是「不在当前 tab 里的内容看不见」。缓解手段是**计数徽标**——审核的五个队列、项目数、交接条数都带数，用户不必点进去才知道有没有东西。这也是为什么本决策把徽标写成硬要求而不是可选装饰。
- **负面（多一层控件）**：知识页于是有外层分段控件 + 内层 tab 两组切换控件。两组形状与位置都不同（胶囊分段 / 下划线 tab），且外层两个抽屉里只有一个有内层 tab，不构成歧义。
- **负面（多一个深链面）**：三个页面各多一个 URL 参数。这是可寻址性的成本，也是 ADR-0038「可寻址性不降」的兑现方式。
- **中性**：审核页的 `pending / rejected / approved` 三个取数照旧在页面 mount 时并行发起——切 tab 不重新取数（数据量与延迟都没变，tab 只是显示层）。
- **中性**：仪表盘的「全部 / 关注」范围开关仍是 chip 而非 tab，**这是有意的**——它切换的是取数范围（连 summary 一起变），不是「看哪一块」。

## 落地记录（2026-11-02）

清单 7 条全部落地。**四处落点与原文写的不一样**，都是原清单低估了改动面或没写到的边角，不是改主意：

- **清单第 1 条多出两个文件**：`web/src/components/TabStrip.tsx` + `TabStrip.module.css` + `TabStrip.test.tsx`（8 例）。样式**复用**设计系统全局已有的 `.tab-btn` / `.tab-active`，没有第二套 tab 外观——新加的三处 tab 和项目页、设置页已有的 tab 看起来是同一件东西。
- **清单第 2 条多了一条原文没写的规则**：社区摘要报告并入「后台任务」tab 之后，**报告跑完自动切到那个 tab**。刚花钱跑完的结果不该要人自己找——它跑完的那一刻用户往往还停在别的队列上。
- **清单第 2 / 4 条的 URL 口径收紧了**：决策 6 写的是 `?view=pending|merge|scope|jobs|rejected`，落地时改成**默认视图不出现在 URL 里**（`/review` 而不是 `/review?view=pending`，`/dashboard` 而不是 `/dashboard?view=projects`）。理由与 ADR-0038 落地时一致：URL 是给人分享的，`?view=pending` 这种默认值写进去只让链接变长，不增加信息。知识页的 `?view=notes` 是例外——`?sub=organize` 必须同时说清自己属于哪个抽屉，否则分享出去的链接不知道说的是「笔记抽屉里的待整理」还是别的什么。
- **清单第 5 条多了一组词条**：审核页原有的 `pendingHeading` / `mergeHeading` / `scopeHeading` / `jobHeading` / `rejectedHeading` 五个小标题 key **被删掉**（tab 标签就是标题，面板不再重复一遍），换成 `tabPending` / `tabMerge` / `tabScope` / `tabJobs` / `tabRejected`；另加 `tablistLabel`（tablist 的 aria-label）、`rejectedHint`（错误页面板里那句「已被替换」）和 `emptyTab`（空面板提示）。知识页的 `organizeJump`（「待整理 N」跳转按钮）随按钮一起删除。

落地过程中修掉五个真问题，都不是「发现的小瑕疵」：

1. **选中的 tab 会自己消失**：队列在脚下被清空时（审掉最后一条、合并掉最后一个候选），tab 条把那个 tab 撤了——面板在用户眼前跳走，URL 还留在一个已经不存在的 tab 上；更糟的是下一条同类记录一进来，tab 又出现，面板**突然跳回去**。改成**选中的 tab 永不消失**（`tabs` 的 memo 改成 `approved.length > 0 || view === 'scope'` 这类形式），清空的只是没被选中的那些。
2. **社区摘要跑完不自动切 tab**：报告出来后人还停在「待审核」，得自己数一遍 tab 才知道刚才那笔钱买了什么。改成两种结果都切到「后台任务」（含闸门关闭时的「功能未开启」提示）。
3. **默认视图进了 URL**：`/review?view=pending` 这种链接分享出去毫无信息量。收紧为默认视图不写进 URL，与知识页 `?view=` 的既有口径对齐。
4. **空面板和「加载中」长得一样**：tab 化之后「没有内容」是常见状态，若无其事地留白，用户会以为还在加载。加了 `review.emptyTab`（「这里还没有内容。」/「Nothing here yet.」）。
5. **`aria-controls` 指向一个不在 DOM 里的面板**：非激活面板不渲染（只渲染当前面板是本仓库的既有写法，项目页与设置页一模一样），于是未激活 tab 的 `aria-controls` 是悬空的。**没有只改这三个页面**——改一半会让「tab 的面板该不该常驻挂载」在同一个产品里出现两套答案。记为**已知限制**，全仓修法（所有面板常驻挂载 + `hidden`，含本 ADR 明确不迁的项目页与设置页）另议；而且它不是免费的：审核页「页面作用域」面板光下拉框就约 800 个 `<option>`，全部常驻挂载是有代价的。**当前 tab 的指向永远有效**，悬空的只是未激活 tab 的引用。

诚实性两处，与决策 2 / 4 直接相关：

- **徽标是硬要求，不是装饰**：tab 化意味着「不在当前 tab 里的内容看不见」，计数是用户唯一能判断该不该点进去的依据。**零值也显示**——「待审核 0」是信息，不是噪音。
- **仪表盘的「全部 / 关注」保持 chip 不变**：它切的是**取数范围**（连 summary 一起变），不是「看哪一块」。徽标跟着范围走（真库实测：关注 5 → 全部 18），summary 口径**一字未动**。

真库实测（v2.23.0，31 个项目）：

- `/review`：五个 tab 与徽标全部正确——待审核 0 / 合并建议 20 / 页面作用域 27 / 后台任务 10 / 错误页 18；默认视图不进 URL（`/review`）；点「合并建议」→ `/review?view=merge`，面板切到候选对列表。
- `/knowledge`：笔记视图两个 tab（全部笔记 / 待整理 17）；深链 `/knowledge?view=notes&sub=organize` 直达待整理面板，徽标 17 与面板里的实际条数一致；切回「全部笔记」URL 收干净成 `/knowledge`。
- `/dashboard`：项目 / 会话两个 tab（项目 5 / 会话 4）；点「会话」→ `/dashboard?view=sessions` 且记忆环出现；**后退键回到 `/dashboard` 并选中「项目」**（POP 判据生效）；「全部 / 关注」切换后项目徽标从 5 变 18。

一条代价，记在案里：**tab 条不做 sticky**。三个页面的 tab 条都在各自滚动区的顶部（入口就在第一屏，与旧的「待整理 N」跳转按钮同位置，可达性没有退化）。Review 与 Knowledge 上方已有 sticky toolbar，要再叠一层 sticky 就得靠魔数偏移或者重构 toolbar，收益不足——**但这是本决策明确接受的代价，不是遗漏**。
