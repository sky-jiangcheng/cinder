# ADR-0041: 悬浮按钮改造为可拖拽的 agent 入口，仪表盘作用域成为共享单一真值

- 状态：Accepted（2026-11-03，用户直接提出并拍定形态）
- 日期：2026-11-03
- 关联：[ADR-0024](0024-home-workbench-merge-search-page.md)（首页 = 整页对话台）、[ADR-0038](0038-desktop-information-architecture.md)（数字只有一处权威）、[ADR-0039](0039-in-page-tabs-over-stacked-sections.md)（「全部 / 关注」是范围开关不是 tab）、[ADR-0040](0040-unscoped-ask-orientation-and-handoff-evidence.md)（无作用域问答的取向层）、[ADR-0029](0029-in-app-update-download.md)（安装信息可见）

## 背景

起因是一句用户提问：**「悬浮按钮跟对话的发送按钮重叠了」**，以及紧跟着的一条改造要求——**「这块悬浮对话按钮需要改造为 DSH bot 或者 Trae 的小机器人一样的 agent 入口，可以移动的，并打通桌面 App 各个入口，比如可以问仪表盘的内容、今日代码提交量，直接扩展对话框并给一个卡片」**。

这句话里藏着三件事，一件比一件难。

### 一、两个控件抢同一块像素

旧的悬浮按钮（`QuickCaptureFab`）`position: fixed` 在**右下角**。而知识库对话台（`HomeKnowledgeAssistant`）的发送按钮也在右下角、输入框里。两个控件重叠在几乎同一处，**而用户按的那个是更没用的那个**：发送按钮是对话台的主路径，悬浮按钮只是一个记一笔的小表单。

### 二、悬浮按钮本来就不是 agent 入口

它能做的只有「记一笔」。它**不知道用户在哪一页**，所以关于当前页面的每个问题都得从零打一遍字（"今天提交多少？"、"我最近在改哪个项目？"）。而答案就在页面上——仪表盘握着今日计数，项目页握着那个项目的技术栈与活跃度。**页面已经握着答案，悬浮按钮却只提供一个空白输入框。**

### 三、最难的一条：补上问答之后，两个数会互相打架

这是本篇真正要解决的问题，也是最容易被做错的一条。

仪表盘显示的「今日代码量」**取决于两个用户做的选择**：**看哪一天**（日期选择器）与 **只算星标项目还是全部仓库**（「全部 / 关注」范围开关，ADR-0039 决策 4 明确它是范围开关不是 tab）。

实测（v2.24.0 真库，日期 2026-11-02）：

| 口径 | repo_count | total_added | my_added | my_deleted | my_files |
|---|---|---|---|---|---|
| **星标**（仪表盘默认） | 6 | 768 | **371** | 318 | 13 |
| **全库** | 7 | 20,689 | **10,327** | 3,236 | 149 |

仪表盘的汇总条跟着范围开关走，默认给 **371**（与首屏的「今日目标 371 / 500 行」同一个数）。

于是：

- 如果 agent 按**全库**取数，它会说 10,327——**同屏两个数，差 28 倍**，用户无从判断哪个才是 app 的答案；
- 如果 agent 按**墙钟当天**取数，它会在早上显示「0 次提交」，而旁边仪表盘显示 371 行——**同一个问题，两个数**；
- 如果 agent 按昨天取数但口径不对，它会说 768（团队口径）而仪表盘的「个人新增」是 371——**连名字都对不上**。

ADR-0038 决策 5 已经写过一句话：「**数字只有一处权威**」。本篇要做的，是让这个 agent **不再成为第二处权威**。

## 决策

### 1. 悬浮按钮改造为可拖拽的机器人

- `AgentBot.tsx` 取代 `QuickCaptureFab.tsx`：52×52 的机器人按钮，pointer events 拖拽，**4px 阈值**区分「点击」与「拖拽」（低于阈值按点击处理，高于阈值只挪位置不开面板）。
- **默认落在左下**（侧栏宽 72 + 20），**而不是右下角**——右下角是对话台发送按钮的地盘，左侧栏边缘在每一页都是空的。
- 位置由用户说了算：拖完写进 `localStorage`（`repotory.agentBot.pos`），下次启动还在原处；窗口缩放时重新夹在视口内。**会自己挪位置的悬浮控件就是会挡路的悬浮控件。**
- 键盘可达：Enter / Space 开合，Escape 关面板。

### 2. 点开就是一张卡片，不是一个空白输入框

**打开面板即给出当前页面的那一张卡片。** 一个开起来是空白输入框的 agent，等于什么都没说；一个开起来就说「今日提交量 39」的 agent，已经回答了用户本来要问的问题。

### 3. 上下文随路由走

`agentContext.ts` 按当前路径给出该页能回答的问题与卡片：

| 页面 | 快捷问题 |
|---|---|
| 仪表盘 | 今日提交量 / 近 7 天 / 待办与笔记 / 最近一次提交 |
| 项目页 | 项目概览 / 该项目今日提交 / 最近提交 / 技术栈 |
| 审核 | 待审核页面 / 今日提交量 |
| 知识库 | 待办与笔记 / 今日提交量 |
| 知识页 | 最近交接记录 / 今日提交量 |
| 设置 | 安装信息 / 今日提交量 |
| 首页（对话台） | 最近交接记录 / 今日提交量 |

自由提问时，作用域也跟着页面走：项目页问的是**那个项目**，其余页面问的是**全库**。

### 4. 卡片走本地数据，自由提问才走 AI

卡片用**页面自己在用的那套数据**取数：精确、即时、**不需要配 AI 端点**。「今日提交 39 次」是一个事实，不是一次猜测。自由提问才走 AI 流式问答（沿用 ADR-0040 的取证层与引用编号）。

### 5. 仪表盘作用域成为共享单一真值

新增 `web/src/state/dashboardScope.ts`：**日期 + 星标开关**由仪表盘写、agent 读。

```
仪表盘（写）──► dashboardScope ◄── agent（读）
```

这不是抽象洁癖，是第 3 节那张表的直接后果：**两个消费者读同一份选择，两边就不可能对不上。** 它是一个极小的外部 store（不是 React context）——两个消费者根本不在同一棵树的同一个位置（仪表盘是页面，机器人挂在 App 根），store 免得它们非得是兄弟。

作用域因此**跨路由保留**：用户在仪表盘切到「全部」，走到知识库再回来，仍是「全部」——用户的选择不该因为他走开一趟就丢掉。（跨重启不保留：store 在内存里，重启回到默认。）

### 6. 卡片与仪表盘同口径

卡片取 **`my_added` / `my_deleted` / `my_files`（个人口径）**，与仪表盘汇总条的「个人新增 / 个人文件 / 仓库」**逐字相等**。

唯一**故意不同口径**的是**提交数**：它来自热力图，而热力图没有星标过滤，统计的是**全部仓库**里用户的提交数——这也正是仪表盘自己的热力图显示的那个数。**所以卡片脚注必须写明**：

> 代码行与仪表盘「个人新增」同口径（星标项目）；提交数取自热力图，统计全部仓库。

不写，脚注就是在替两个数打架打掩护。

### 7. 日期诚实

scope 的日期不是昨天时（用户在看别的日子），标题与 chip **都不说「今日」**，改说「代码提交量」，卡片副标题**始终写具体日期**。一个写着「今日提交量」却答 2026-01-01 的卡片，是在说谎。

### 8. 旧能力不丢，只是换了个位置

- 旧 `AIAskPanel` 的能力（证据问答、存为笔记、存为知识页）**收进 agent 面板的 AI 卡片**；
- 旧 FAB 的记录表单**抽成 `QuickCapturePanel`**，作为 agent 面板里的「记一笔」模式；
- 两个旧文件（`AIAskPanel.tsx` / `QuickCaptureFab.tsx`）及其样式删除。

### 9. 不动的东西

不改后端、不改 schema、不改 `internal/app` 绑定、不改 ADR-0038 / 0039 / 0040 的任何决策、不改品牌三域结构、不改知识库对话台本身。

## 后果

- **机器人默认在左下，会盖住页面左下角的内容**（首页的「热门项目」区就在那儿）。这是悬浮控件的固有代价，**可拖动就是解法**，也是用户明确要的形态。
- **提交数与代码行数跨口径**（热力图无星标过滤），所以脚注是硬要求，不是装饰。
- **作用域改成共享 store 后，仪表盘的日期与范围开关跨路由保留**——这是行为变化（以前离开仪表盘再回来会重置），但它正是「agent 与仪表盘永远说同一个数」的前提。
- **读失败仍然如实报错，不回落成 0**：「0 次提交」是关于用户当天的事实，读失败时说 0 是用户无法察觉的谎。
- **卡片只给事实，不给建议**。它回答「是多少」，不回答「你打算怎么办」——后者是 AI 那条路的事。

- 机器人按钮实测在 `(92, 685)`，尺寸 52×52 —— **左下角**，与对话台发送按钮（实测在 `x=568, y=304`，输入框右下）**完全不重叠**；
