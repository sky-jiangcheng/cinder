# ADR-0038: 桌面端信息架构收口——一个动作一个入口，同一对象两态切换

- 状态：Accepted（2026-11-02，用户直接提出问题并拍定取舍）
- 日期：2026-11-02
- 关联：[ADR-0024](0024-home-workbench-merge-search-page.md)（**本文 supersede 其决策 1**，并修订其决策 2、3 的落点）、[ADR-0034](0034-desktop-three-column-shell.md)（外壳三栏结构不变，右栏的搜索入口按本文删除）、[ADR-0036](0036-ide-chat-console.md)（**桌面端首次对齐它的对话台模型**）、[ADR-0032](0032-approved-knowledge-page-visibility.md)（知识页的只读语义不变）、[ADR-0017](0017-one-kernel-two-entry-points.md)（仪表盘「不移出首屏」的原则以新方式兑现）

## 背景

用户在用桌面端时指出：首页 / 仪表盘、知识库 / 知识页这两组 tab「元素有些冗余或者错乱」，并追问首页的对话框与搜索是否该合并到一处。

这不是审美意见，是**同一份数据在多处各画一遍**。逐条核对代码后的实况：

| 数据 | 出现位置 | 冲突 |
|---|---|---|
| 项目列表 | 首页「重点项目速览」3 张速览卡 / 仪表盘 ProjectCard 列表（关注 + 其他） | 两种卡片形态、两种截断口径 |
| 新增行数 | 首页「今日开发动态」/ 仪表盘 GoalRing + SummaryBar | 首页取 `getSummary('')`（全量），仪表盘取**选定日期** |
| 仓库数 | 首页「仓库数」= `projects.length`（项目表行数）/ 仪表盘「涉及仓库」= `summary.repo_count`（真有 git 仓库的计数） | **同屏两个数，可能不等**——首页代码注释自己承认这个口径差，但用户只看到矛盾 |
| 搜索输入框 | `/search` 大输入框、`/knowledge` 顶栏、`/wiki` 顶栏、仪表盘项目下拉 + 右栏输入框 + ⌘K CommandPalette | **同一个动作 6 个入口**，各自独立实现 |
| 最近列表 | 首页「记忆环」（最近交接记录）/ 右栏「最近更新」（最近知识页） | 两列都叫「最近」，语义却不同 |
| 知识页 | `/wiki` 列表 / 右栏「最近更新」/ `/search` 命中 | 三处 |

而**知识库与知识页的 UI 骨架几乎一样**（搜索框 + 筛选行 + 结果计数 + 列表），检索的却是两种不同的东西：前者是**原料面**（笔记 / 待办，可写、可整理、可导入），后者是**成品面**（已批准页，只读）。两个平级顶级 tab 把「原料」和「成品」摆成对等关系，用户得自己判断该去哪；更别扭的是**能力不对等**——知识页有项目作用域下拉，知识库没有，可知识库的检索本来就是跨项目的。

**对话框与搜索是同一件事的两副面孔**：一个给带出处的答案（`AskAIWithEvidence`，ADR-0033），一个给命中列表。它们分居两页，首页还给自己开了一个跳去搜索页的链接。

**流式展开这块，桌面端从来没设计过。** 对话卡的 DOM 顺序确实是「标题 / 流 / 输入区常驻底部」（与 ADR-0036 给两个 IDE 定的对话台同构），但它被塞成一张 `min-height: 520px`、内部 `.chatStream` 自带滚动（`max-height: 580px`）的**卡片**，嵌在会滚动的页面里——**两层滚动区**。这不是「展开」，是**把对话关进一个盒子**：问得越多，卡片越满，页面还得另滚一次才够看。搜索页则是整页布局，**没有折叠态**。

根子上是一件事：**这七个顶级 tab 是三种东西混在了一个平级导航里**——动作面（问 / 搜）、对象面（看笔记 / 看页 / 看项目）、事务面（审核 / 设置）。同一种东西被拆成平级入口，冗余与错乱是必然结果。

## 决策

### 1. 顶级入口收敛为五个

`首页 · 仪表盘 · 知识 · 审核 · 设置`。

- **首页 = 问 + 搜**（见决策 2、3）：它是「向知识库要东西」的唯一入口。
- **仪表盘 = 今天**（见决策 5）：唯一一处「我的产出」。
- **知识 = 笔记 / 知识页**（见决策 4）：同一个知识对象的两种状态。
- **审核 / 设置** 不动。

`/search` 不再是顶级 tab，路由重定向到 `/` 并保留 `?q=` 深链；`/wiki` 重定向到 `/knowledge?view=pages`，`/wiki/:id` 详情路由保留（深链与已分享链接不受影响）。

### 2. 首页 = 整页对话台：唯一滚动区 + 输入区常驻底部

- **空闲态**：整页居中一个大输入框 + 推荐区。推荐**合并三处**来源：热门项目、热门标签（承接 ADR-0024 决策 3）、快捷提问（今天分散在 `/search` 空闲态与对话框空态里）——**一处权威**。
- **发起后**：输入区**常驻页面底部**，对话 / 结果流**成为页面唯一的滚动区**，头部收成一条状态条。
- **不做「展开」按钮**：布局由「有没有对话」决定——这是两套形态，不是一个动画。
- 这是**桌面端第一次对齐 ADR-0036 的对话台模型**（对话流是唯一滚动区 / 输入区常驻底部），此前该模型只落在两个 IDE 面板上。

### 3. 问 / 搜双模式：同一个输入框 + 一个显式模式开关

- **问**（默认）：流式答案 + `Sources:` 出处清单（复用 `askAIWithEvidenceStream`，可中断）。未配置 AI 端点时走本地检索回退，并**明说「这是关键词匹配不是答案」**（ADR-0033 决策 2）。
- **搜**：命中列表（笔记 / 待办，按项目分组）。
- **不靠猜**：模式由用户显式切换，不靠「回车还是点按钮」区分。
- 两个模式**共享同一个项目作用域选择**——这是它们唯一的耦合点：一条命中可以被「就这条追问」，把搜索结果接进对话流。

### 4. 知识 = 一个 tab，两视图，一套骨架

- 路由 `/knowledge`，内部两个视图：**笔记**（默认）/ **知识页**，用分段控件切换，URL 带 `?view=`（可深链）。
- **骨架共享**：同一个搜索框、**同一个项目作用域下拉**、同一个结果计数条、同一套空态与错误处理。
- **身体不同**：笔记视图是网格 + 筛选（全部 / 知识 / 其他、置顶、标签、主题）+ 写作动作（新建 / 导入 / 待整理）；页视图是列表 + 只读（**只列已批准页**的语义一字不改，ADR-0032 决策 1 仍然成立）。
- **作用域下拉补给笔记视图**——现状缺这一项，检索本来就是跨项目的。

### 5. 数字只有一处权威：仪表盘

- 仪表盘是**唯一**的「我的产出」面：目标环、统计条、热力图、控制行、项目列表、状态栏，全部保留不动。
- **首页删除**「重点项目速览」（3 张速览卡）与「今日开发动态」卡——前者与仪表盘项目列表重复，后者与仪表盘统计重复且口径不一致。首页不再自己算项目数与新增行数。
- 删除首页指向仪表盘的「进入完整仪表盘」链接（首屏已有直达 tab）。
- **记忆环（最近交接记录 + 写一条交接记录）挪进仪表盘顶部**，作为「上次的会话」——它属于「我的状态」，不属于「我要答案」；且「写一条交接记录」是零配置进入会话循环的唯一入口，仪表盘同样是首屏可达。

### 6. 搜索入口收敛

- **右栏的全局搜索输入框删除**（对话台已有输入框，⌘K CommandPalette 保留）。右栏回到 ADR-0034 定的「待审核 + 最近更新」两块。
- **知识 tab 内的两个搜索框保留**——它们是**各自视图内的筛选**，不是全局检索，与对话台的「问 / 搜」不是同一件事。
- 仪表盘的项目下拉**保留**（它是项目筛选，不是全局检索）。

### 7. 不动的东西

不改 schema、不新增 MCP 工具、不新增 `internal/app` 绑定、不改品牌名与图标三域结构；不动两个 IDE 面板（它们已是 ADR-0036 的对话台形态）；不动问答与检索的后端语义（`askAIWithEvidence` / `searchAll` / `browseWikiPages` 全部复用）；不动 `/project/:id` 项目页与审核页的既有职责。

## 后果

- **正面**：顶级入口 7 → 5；同一份数据只有一处权威呈现，「仓库数」这类自相矛盾的数字从根上消失；首页从「四个性质不同的东西各做一半的杂烩」变成一个意图明确的对话台；知识 tab 把「原料 / 成品」的关系显式化；桌面端与两个 IDE 面板第一次说同一种交互语言（ADR-0036 的模型）。
- **正面（可寻址性不降）**：`/search?q=`、`/wiki?project=`、`/wiki/:id` 三类深链全部保留（重定向到新落点），IDE 面板与 `repotory://` 深链走 MCP / HTTP，不依赖网页路由，不受影响。
- **负面（入口减少的代价）**：老书签与文档引用指向 `/search` / `/wiki` 时会经过一次重定向（一次性迁移成本，ADR-0024 决策 1 当初也是这么算的）；首页不再一眼给出「今天产出了多少」——要看仪表盘；知识 tab 从笔记到页多一次视图切换。
- **负面（对话台的重）**：首页从一张 520px 卡片变成整页对话台，首屏承载的信息密度显著上升；空闲态的推荐区必须够有用，否则首屏会显得空——这是本决策**唯一必须实测**的点。
- **中性**：左右两栏外壳（ADR-0034）不动；右栏少一块，但它的两条内容（待审核、最近更新）本来就是「不离开当前页面也能看到」的上下文。
- **中性（与 ADR-0024 的关系）**：本文 supersede 它的决策 1（首页工作台化），并把它的决策 2（全局搜索独立成页）、决策 3（热门推荐）**改落点**——搜索不再独立成页，热门推荐改落对话台空闲态。ADR-0024 原文保留作历史。

## 落地记录（2026-11-02）

清单 12 条全部落地。**三处落点与原文写的不一样**，都是原清单低估了改动面，不是改主意：

- **清单第 3 / 4 条实际是分工，不是两块代码**：`Home.tsx` 瘦身为「加载项目列表 + 渲染对话台」两件事，对话台的主体（模式开关、两套布局、推荐三源、URL 同步、命中分组）全在重写后的 `home/HomeKnowledgeAssistant.tsx` 里，`Home.tsx` 只剩 60 行。
- **清单第 9 条的文件是被删掉，不是被「并入」**：`web/src/pages/Search.tsx` 连同 `Search.module.css` / `Search.test.tsx` 一并删除。检索能力没有搬家，是**在对话台的「搜」模式里重新实现**（`searchAll` + 客户端按项目分组 + 项目名匹配单列一组）。
- **清单第 5 / 6 条多出一个新文件**：`web/src/hooks/useKnowledgePage.ts` 承接两个视图共享的状态（查询词防抖、作用域、笔记与命中）。`Knowledge.tsx` 是共享骨架（分段控件 + 一个搜索框 + 一个作用域下拉 + 一个计数条 + 统一 ErrorBanner/loading），`Wiki.tsx` 降为页视图身体（`WikiPagesView`），两者共用同一套状态钩子。

落地过程中修掉四个真问题，都不是「发现的小瑕疵」，而是会让界面说错话：

1. **分组标题空白**：后端 `SearchAll` 的 `project_name` 是 NULL（join 留空），按项目分组时标题直接是空的。回退链定为 `hit.project_name` → 项目列表 → `#id`——**最后一级是诚实的底线**：名字真的查不到时显示 `#124` 而不是编一个。
2. **提交后输入框没清空**：根因是 react-router 的 `setSearchParams` 走 transition，**中间有一帧 URL 仍持有旧值**；原先「URL 变了 = 外部改动」的判据把那一帧读成了外部改动，把用户刚提交的词又填回输入框。判据收紧为**只有 `useNavigationType() === 'POP'`（后退 / 前进）才算外部改动**，自己的写入一律走 `written` ref 记账。
3. **深链 `/?q=` 首跑不自动检索**：修完第 2 条的判据后不再复现。真库复验：`/?q=交接` 与 `/search?q=交接` 都直接进入搜模式，给出 7 条命中并按项目分组（`Script 7`）。**此处不写根因**——两个症状同源于同一个 URL 判据缺陷，改完即不复现，再编一个没验证过的解释反而是给未来的读者埋雷。
4. **检索入口收敛后，`SearchAll` 的调用方从 1 处变 0 处**：旧搜索页删掉后，全局检索只存在于对话台。`SearchAll` 的后端语义没动，但**它的前端调用面变窄了**——这一点记在案，免得日后有人按旧搜索页的用法去改后端。

诚实性收紧三处，与决策 2 / 3 / 5 直接相关：

- **状态胶囊不再写死 "Live"**：改为如实显示「AI 已连接」或「本地检索」。写死的呼吸灯在 AI 端点掉线时是**假话**。
- **本地回退回复挂徽章**：「这是关键词匹配，不是答案」。没有 AI 端点时答的是命中列表，必须在**回答所在的那一行**说清它不是答案，不能只在别处提示。
- **热门项目推荐不显示数字**：排序仍然用 `my_added_7d`，但推荐位上**一个数字都不给**——数字只有仪表盘一处权威（决策 5）。给了数字，就等于首页又在自算一遍产出。

**一条给下一个人的环境警告**：机器上装着的 `repotory-server` 可能是**旧版本二进制**（本机装的是 v2.18.0，工作区源码已是 v2.23.0）。旧二进制里没有 `BrowseWikiPages` 这个 binding，「知识页」视图会直接报 `unknown method: BrowseWikiPages`——**看起来像前端 bug，其实是后端没换**。`scripts/dev.sh` 已经写明「端口被占用时可能是个旧 build，要 `pkill` 后重启」。排查这类「某个 tab 报 unknown method」之前，先 `curl /health` 看版本号。
