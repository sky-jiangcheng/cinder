# ADR-0042: 页面骨架收口——固定头部 + 独立滚动区，滚动条不再越过 tab 条

- 状态：Accepted（2026-11-03，用户直接指出并拍定取舍）
- 日期：2026-11-03
- 关联：[ADR-0034](0034-desktop-three-column-shell.md)（三栏外壳与内容列留白）、[ADR-0039](0039-in-page-tabs-over-stacked-sections.md)（页内 tab 化；本篇推翻其中「tab 条不做 sticky」那条**已接受的代价**）、[ADR-0038](0038-desktop-information-architecture.md)（桌面端信息架构）

## 背景

起因是一句用户反馈（附桌面端 1360×860 截图，红框标在滚动条的上半段）：

> **「我打红框的地方滚动条不应该滚动到那么高吧，知识库，审核，设置的 AI 等操作界面滚动条都滚动到 tab 顶部了。」**

这句话说的是**滚动条的高度**这件事，但根子在**滚动区的起点**。

### 一、用户看到的那条线

截图里是审核页（v2.27.0 桌面端，深色主题）：

- 竖直滚动条在 `x=1064..1072`，**从 `y=28` 开始**——那是内容列的最顶端，在工具栏上方；
- tab 条（待审核 / 合并建议 / 页面作用域 / 后台任务 / 错误页）在 `y=186`。

也就是说：**滚动条的轨道比 tab 条高 158px**，那段轨道对应的内容是「工具栏 + 导语」，它们是可以被卷走的。用户的意思是：**滚动不该越到 tab 条上面去**。

### 二、为什么会这样：滚动容器里装着 tab 条

外壳的中栏 `.mainContent` 是滚动容器（`overflow-y: auto`），而**工具栏、tab 条、页面内容全在它里面**。于是：

1. tab 条是内容的一部分 → **它会随内容被卷走**（审核页的 tab 条只在首屏可见，滚下去就没了）；
2. 滚动条的轨道从内容列顶端起算 → **顶边永远在 tab 条上方**。

这两条是同一件事的两面：**tab 条没有被固定，滚动区也就没有从它下面开始**。

### 三、顺带查出的第二件事：三处 sticky 魔数早就和外壳的留白脱钩

ADR-0034（提交 `3204df2`）把 `.mainContent` 的 padding 从 `32px` 改成了 `24px 28px`，但 Review / Knowledge / Settings 三处的 sticky 偏移仍按 **32px** 写死（768px 断点还按 **20px** 写死，而实际那里是 **16px**）。于是：

- `top: -32px` + `margin-top: -32px` + `padding-top: 32px` 这套「负边距 + 补回内边距」的固定条写法，**算的是已经不存在的 32px**；
- 固定条与滚动区顶边**错位 8px**（窄屏 4px）；
- 这些数字散落在三处 CSS 里，各自抄了一份 32px / 20px——**同一件事在三个地方各写一遍**，正是 ADR-0034 改外壳时没跟着改的那一处。

### 四、而仪表盘与项目详情页，早就是另一种写法

`Dashboard.module.css` 与 `ProjectDetail.module.css` 里各有一份 `.page` / `.fixed` / `.scroll`：**固定头部 + 独立滚动区**，滚动区的起点天然在头部之下。也就是���：

- **项目详情页本来就是对的**（tab 条在 `.fixed` 里）；
- **仪表盘把 tab 条放进了 `.scroll`**，所以它同样会被卷走；
- 同一件事（页面骨架）在仓库里有**三份各写一遍的拷贝**（仪表盘 / 项目详情 / 外壳），而 ADR-0039 记录的那条代价「tab 条不做 sticky」——**它明确写着自己不是遗漏，是接受的代价**。

## 决策

### 1. 一套页面骨架：固定头部 + 独立滚动区

新增共用组件 `web/src/components/PageShell.tsx` + `PageShell.module.css`，三段式：

```
<PageShell header={…固定头部…} footer={…底部状态条…}>{…滚动区内容…}</PageShell>
```

- **头部**（工具栏 / tab 条 / 横幅）不滚动；
- **滚动区**是页面自己的滚动容器（`flex: 1; min-height: 0; overflow-y: auto`）；
- **底部**（状态条）可选，同样不滚动。

仪表盘 / 项目详情 / 知识库 / 审核 / 设置**五个页面统一用它**，各自模块里那份复制的 `.page` / `.fixed` / `.scroll` 随之删除——**「这一页往哪滚」从此在全产品只有一个答案**。

### 2. tab 条是 chrome，住在固定头部里

**滚动区从 tab 条之下开始**。于是用户要的那条线成立：

> **滚动条的顶边 = tab 条的底边。**

tab 条不再可能被卷走，也不再需要 `position: sticky`——它不在滚动区里，天然不动。

### 3. 不用魔数偏移来固定

固定条**靠「在滚动区之外」固定**，不再靠 `top: -32px` + 负边距那套补偿写法。ADR-0034 造成的 8px 错位随之消失。

左右留白改为**一个变量**：外壳的 `.mainContent` 声明 `--main-gutter`（宽屏 28px / ≤768px 16px），各页满幅（bleed）的偏移一律读它——**同一件事不再在三个地方各抄一份数字**。

### 4. 切 tab 回到「面板顶部」

切 tab 后滚动区自己归零（`scrollTo({ top: 0 })`）。原先是 `scrollIntoView` 到 tab 条（靠 `scroll-margin-top` 避开固定条）——**tab 条已经不动了，那个滚动目标也就不存在了**，语义换成用户真正要的那件事：换区后从新面板的开头读起。

### 5. 滚动条的位置与内容宽度一字不变

滚动区把滚动条**拉回内容列右缘**（`margin-right: -gutter` + `padding-right: gutter`）：滚动条仍在今天的位置（截图里那条 `x=1064` 的竖线），**不会盖住内容**，**内容的可用宽度也不变**。

### 6. 不动的东西

**不动 schema / 后端 / MCP 工具 / 绑定 / 数据口径 / ADR-0039 的任何决策**（tab 化本身、徽标硬要求、URL 口径一个不改）；**不动品牌与图标三域**；**不动首页对话台**（ADR-0038 的整页对话台有自己的布局与滚动区）；**不动 ADR-0034 的三栏外壳**。

## 后果

- **推翻了 ADR-0039 明确接受的那条代价**。ADR-0039 结尾写着「tab 条不做 sticky……**但这是本决策明确接受的代价，不是遗漏**」，理由是「tab 条都在各自滚动区的顶部，入口就在第一屏，可达性没有退化」。**这条推理被用户实测反馈否掉了**：tab 条是这一页**唯一的分区开关**，它一被卷走，用户要换一个区就得先滚回去——「可达性没有退化」只在**首屏**成立。这不是遗漏，是**当时的取舍被后来的事实推翻**，因此由本篇显式改写（ADR-0039 原文保留，只加指向本篇的修订说明）。
- **审核页的顺序变了**：tab 条原来在导语**下面**，现在在导语**上面**（chrome 归 chrome，内容归内容）。设置页与项目详情页本来就是「tab 条在上」这个顺序。
- **固定头部占的高度不再随内容走**。仪表盘的头部本来就很高（hero + 汇总条 + 热力图 + 控件），加上 tab 条之后，滚动区更矮；这是「头部固定」这件事本身的代价，不是副作用。
- **滚动容器换了主人**：这五个页面的滚动由页面自己负责，外壳的 `.mainContent` 对它们不再滚动（首页、搜索结果等其余页面仍由外壳滚）。
- **滚动条与内容的关系变了**：滚动条不再覆盖工具栏与导语那段区域——那正是用户截图里红框标的那一段。
