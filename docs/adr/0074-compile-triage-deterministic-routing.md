# ADR-0074：编译前置分流——用结构信号替代小模型，治草稿成本与 40% 拒绝率

- 状态：**Accepted（2026-11-24，用户选定 ADR-0065 gap 2.6「先做小模型分流」；落地形态改为确定性规则，理由见决策 1）**
- 日期：2026-11-24
- 关联：[ADR-0065](0065-hindsight-absorb-not-replace.md)（gap 2.6 候选吸收项）、[ADR-0015](0015-w3-minimal-compile-loop.md)（编译只写 pending / 不接定时器，本篇不动）、[ADR-0071](0071-fusion-tuning-weighted-rrf.md)（kind 降权否决的教训）、`docs/product-review/2026-11-23-hindsight-experience-gap.md`

## 背景

Hindsight 的 `retain` 用一个 0.8B 决策小模型给流水账分流，只有「改变/新增」才进大模型起草，省约 40% 调用。Cinder 的 wiki 层真问题同源：2026-10-20 人审 12 张 pending 页拒 10 张，拒因几乎全是会话日志复述、导入包装、纯出处标注；存量 45 页里 18 张 rejected（40%）。编译提示里那句「纯日志请输出 []」从来没解决这件事——**模型已经被调用了，钱已经花了**，输出 `[]` 只是没写页。

用户 2026-11-24 选定「先做小模型分流」治成本与拒绝率。本篇记录落地形态与理由。

## 事实（活库只读核对，2026-11-24）

- 162 条笔记：`log` 94 / `knowledge` 67 / 空 1。**流水账占 58%**。
- 94 条 log 里只有 **1 条**带明确决策标记；标题形状高度集中：`<environment_context> · <id>`、`# AGENTS.md instructions for ...`、`Session Handoff`。
- 现有 prompt 里的软规则（`askCompilePlan`：「纯日志输出 []」）无法省调用，且模型不一定遵守。

## 决策

1. **不用第二个模型，用确定性规则**。Cinder 只有一个 AI 端点（ADR-0065 落地记录已定「本地模型不强，用符合规范的远程 API」），引入本地小模型会破坏零 CGO 单文件分发；而用同一个远程端点做分类，每条笔记多一次调用——对被放行的笔记成本翻倍，对被拦下的笔记净省有限。**结构信号已经够用**：活库里 58% 的流水账带同一种 `kind` 与标题形状，规则判定零 token、零延迟、零端点、可单测。用户的目标是「分流治成本与拒绝率」，小模型是 Hindsight 的手段而非目标。
2. **两条信号，且都可被决策标记覆盖**：① 标题以 `<environment_context>` / `agents.md instructions for` / `session handoff` 开头；② `kind=log`。任一命中即跳过；标题或正文含明确决策/规则标记（决策: / 决定: / 规则: / decision: / convention: / 架构决策 / 设计决策 等）则保留——那 1 条真有内容的 log 不误伤。**没有正文长度规则**：ADR-0071 已经量过 kind/长度类启发式会连真答案一起降，本次不重犯。
3. **分流在截断之前**（`CompileNoteTargets` 之前）：若最新 20 条全是流水账，先截断再过滤会把整轮预算浪费光。同步 `CompileProjectNotes`、异步 `runCompileJob`、单条 `CompileNote` 三条入口共用同一判定与同一开关，不能因入口不同而绕过。
4. **默认开，kill switch 为 `wiki_compile_triage=0`**：与其他模型闸门相反（那些默认关是因为 sending text out 要用户授权，ADR-0012），分流不发文本、不写库、只省调用，安全态就是有用态。设置页不新增控件（`wiki_compile` 同样没有 UI 开关）；关闭方式走既有 `UpdateConfig('wiki_compile_triage','0')`。
5. **跳过必须可见**：跳过的条数写进 `Stopped`（异步 job）或 `LLMNote`（同步报告），单条编译给出具体理由——不做静默的部分成功，沿用 ADR-0015 的可见性纪律。
6. **不动任何写语义**：分流只决定「哪条笔记值得花一次模型调用」，不决定页面写什么、更不决定批准。人审闸门（ADR-0015）、新 ADR-0073 的可选自动放行、schema 与 MCP 工具面全部不变。

## 代价

- `kind=log` 里那类「标题不像流水账、正文也没写决策、但实际有知识」的笔记会被误跳过（活库未见，但理论上存在）。补救是改 `kind` 或在正文写一句明确的决策标记——两者都是人一次编辑，比关掉整个分流划算。
- 决策标记是关键词表：规避它很容易（写「我们定了 X」不写「决定: X」），但它只用于**救回**日志，不用于放行其他内容，误判方向是保守的。
- 结构信号绑在 importer 的标题/`kind` 约定上；若某个 importer 改了输出形状，分流会漏拦。翻转条件见下。

## 验证

- 纯函数 9 条规则用例（含「带决策的 log 保留」「短但真实的笔记保留」两条防误伤断言）。
- seam 级断言：流水账笔记触发 `CompileNote` 时 **`chat.calls == 0`**——成本收益在数据链路上被证明，不是从报告文案推断。
- kill switch 断言：缺省 / 空 / 乱码均为 ON，显式 `0` 为 OFF；关闭后同一笔记恢复 1 次调用。
- 全量 `go test ./...`、`go vet`、前端 tsc/vitest/build 见当次发版记录。

## 翻转触发

- 若出现稳定的「log 类但有真实知识」误跳过反馈 → 扩充决策标记，或给该类笔记手动改 `kind` 成为一条显式规则，不恢复到「全量送模型」。
- 若 importer 标题/`kind` 约定变更导致分流漏拦 → 随 importer 同批更新 `transcriptTitleMarks`，加一条真机样本断言。
- 若将来 Cinder 真的有了零 CGO 本地小模型（随二进制分发）→ 可把 `CompileTriage` 换成一个可选模型判定，但默认仍留确定性规则作兜底与成本下界。
