# ADR-0078：笔记有自己的地址——`/note/:id` 详情路由

- **状态**：Proposed（2026-11-24，用户提出「知识点进详情是详情页，笔记进详情却进了项目」并选择落码）
- **日期**：2026-11-24
- **关联**：ADR-0023（笔记归属与知识库整理——本篇修订其「点笔记直达」的落点）、ADR-0038（桌面信息架构——「知识 = 笔记 / 知识页」）、ADR-0032（知识页只读详情路由 `/wiki/:id`）、ADR-0057（笔记乐观锁版本号）

## 背景

同一个「点一条知识记录」的动作，两种记录两种结果：

| | 知识页 `wiki_pages` | 笔记 `project_notes` |
|---|---|---|
| 归属列 | `project_id` **可空** | `project_id` **NOT NULL** + FK CASCADE |
| 地址 | `slug UNIQUE` | 无 slug，只有自增 id |
| 前端路由 | `/wiki/:id`（`App.tsx`） | **没有 `/note/:id`** |
| 点击后落到 | 自己的详情页 | `/project/<pid>?tab=notes&noteId=<n>` |

这不是遗漏。ADR-0023 把这条痛点写进了原文（「知识库点笔记只跳到项目、看不到那条笔记本身」），当年的修法是**深链 + 高亮**：跳到所属项目的「笔记」tab，滚动到那张卡片并闪一下。理由是笔记必然属于某个项目，「详情」就是「项目上下文里的那一条」，不新增独立实体就不用动 `NOT NULL` 与它牵连的 FTS / embedding 队列 / 级联。

这个理由在「记录有归属」这一点上成立，在**阅读与引用**上不成立：

1. **地址带着项目走**。所有入口都拼两个 id（知识库、右栏、首页证据卡、仪表盘交接环、审核页来源笔记、知识页来源笔记，共 9 处）。`MoveNote` 把笔记换项目之后，旧链接落在旧项目里且找不到那条笔记——一条记录的可寻址性取决于它当时住在哪，这本身就是坏味道。
2. **读一条笔记要经过一个项目页**。落到项目详情 → 切到「笔记」tab → 滚动到卡片，页面带着项目头、tab 条和其余所有笔记。笔记正文是 `NoteCard` 全量渲染的 markdown，笔记一多就是一条几千像素的长滚动页。
3. **知识页能粘贴分享，笔记不能**。`/wiki/17` 发出去就是那一页；笔记只能发一对参数，接收方还得知道那个项目还在不在。

## 决策

**给笔记一个只由 id 构成的地址，读与管分开。**

1. **新增路由 `/note/:id`**（`web/src/pages/notes/NoteDetail.tsx`）。正文按整页阅读面排版（820px、serif 16px/1.7，与 `/wiki/:id` 同一套度量），头部给 kind / 项目 / 主题 / 来源徽标与创建更新时间，正文下方是 编辑 / 历史 / 在项目中打开 / 删除。
2. **数据模型不动**。`project_notes.project_id` 仍是 `NOT NULL`：笔记属于某个项目这件事没有变，变的是**地址不必经过项目**——`GetNote(noteID)` 已在绑定面上，笔记自己带着 `project_id`，页面用它做范围徽标和「在项目中打开」。
3. **跨页跳转统一改指 `/note/:id`**：知识库网格卡、知识库搜索结果、右栏证据卡、首页问答证据卡与搜模式命中、仪表盘交接环、审核页与知识页的「来源笔记」chip。待办不动——待办没有行级地址，继续落 `/project/:pid?tab=todos`。
4. **`?noteId=` 保留**。项目详情页仍认这个参数并滚动高亮（老链接、外部深链、笔记页的「在项目中打开」都走它），`/project/:pid?tab=notes&noteId=<n>` 从「唯一入口」降为「管理入口」。
5. **返回来源由 `state.from` 决定**：列表页把自身 URL 作为 `state` 传过去，「返回笔记列表」回到那条搜索/那个作用域；直接打开的深链没有 `state`，回落到 `/knowledge?view=notes`。
6. **项目内笔记卡改为「标题即链接 + 正文可折叠」**：标题进笔记页，正文超长时默认折到约 168px 并给「展开全文」（弱化遮罩，不是硬切）。项目「笔记」tab 的职责收回到「批量管理」，不再兼任长文阅读器。

## 代价

- 多一个页面与一条路由，笔记的编辑/历史/置顶/删除动作在详情页与项目页各有一份入口。共用的是 `NoteEditor` / `VersionHistoryPanel` / `useNoteVersionHistory` / `useNoteMutations`，不是复制出来的逻辑；但两处动作集合需要一起维护。
- 笔记详情页是「读」为主，**没有** AI 整理与新建：这两件事仍然只在项目里的笔记列表发生。少一个入口是刻意的——整理是批量语境下的动作，在单条阅读页放它会把页面变成工作台。
- `/note/:id` 与 `/project/:pid?tab=notes&noteId=<n>` 两种地址并存，笔记被移动后前者仍有效、后者失效，两者不能互相重定向（后者携带的项目 id 已经不对了）。
- 删除当前页所代表的记录后没有落脚点，页面把用户送回该笔记原所属项目的「笔记」tab（`replace`）。

## 翻转触发

- 笔记需要**跨项目的稳定标识**（例如对外分享链接、跨库迁移后仍要能定位）→ 那时才值得给笔记加 slug，本篇的 id 寻址不够用。
- 笔记详情长成**独立工作台**（在页面里编译成知识页、批量整理）→ 与本篇「读与管分开」的前提冲突，需要重新划界面边界。
- IDE 插件与桌面端的笔记深链要统一格式 → 由 `repotory://` 与 MCP 承担，不影响网页路由；本篇不改绑定面。
