## Background

The owner asked: "Research Hindsight — how big is the gap, and should it replace the foundation of Cinder and Warden?" Hindsight (vectorize-io/hindsight) is an agent memory system whose positioning overlaps Cinder's head-on: MIT, Python, ~62.7k stars, v1.2.3 (2026-11-19), maintained full-time by a commercial company, claiming LongMemEval SOTA (independently reproduced by Virginia Tech and The Washington Post; the exact figures were not fetched and verified this round and are not cited). Its `hindsight-coding-agents` package builds a per-repo bank automatically, ingests git history and past sessions, injects curated pages at session start, and wires 22 coding agents with one command — **a competitive signal, not merely a technical comparison**.

## Facts (verified on the research day)

**Hindsight side** (source: GitHub README and docs, fetched via the gh API):

- Storage: PostgreSQL + pgvector (embedded pg0 avoids a separate install); Docker / pip / Helm / managed cloud; **every retain passes through LLM extraction** (entities / relations / time); local Ollama works but there is no zero-model path
- Four memory layers: world facts → experiences → **observations** (automatic consolidation, exact evidence quotes + proof count, new evidence refines a belief rather than overwriting it, near-duplicate reconciliation on by default) → **mental models / pages** (a self-maintaining living wiki, incremental delta refresh, `fs mount` projects pages onto disk as markdown)
- recall runs four strategies in parallel (vector / BM25 / entity-causal graph / temporal) → RRF → cross-encoder reranking
- Three self-trained open-weight small models: decision 0.8B (Apache 2.0) / rerank 114M (MIT) / embedding 112M (MIT), all runnable locally; decision-model triage measured ~40% fewer LLM calls and ~70% fewer input tokens on page refreshes
- Memory Defense: 45 built-in secrets/PII patterns, redact or block, opt-in per bank
- Experience benchmark (AMB sdebench, 61 real repository tasks × 3 runs): memory does not change the solve rate (60–61/61 either way); what moves is **human corrections per task** (Claude Code 0.85→0.36) and token cost ($0.445→$0.338)

**Cinder side** (verified against repository code, correcting two overstatements from the first research pass):

- **RRF already exists** (`internal/search/hybrid/hybrid.go` `FuseRRF` k=60, `fuseSemantic` wired into production `SearchAll`); **evaluation infrastructure already exists** (`cmd/abeval` recall/ndcg, `cmd/searchbench` staged latency, `cmd/queryset`) — the initial "missing RRF, missing eval" judgement does not hold
- ADR-0018 lanes 1/2 are both Accepted and `wiki_graph_search` has been promoted (staged-additive recall + PPR); vectors off by default is ADR-0012's privacy-authorization decision, not a gap
- Real gaps: **no rerank model**; no temporal retrieval channel; **no observations-style evidence-weighted belief revision** (zero grep hits); wiki compile / synthesis gates off by default and expansion halted since 2026-10-29 (insufficient supply, 27 approved / 40% rejection rate); one-click wiring covers only four desktop clients (`internal/agentinit`), no `install all` CLI; the only hook is Claude Code SessionEnd, off by default, **no SessionStart injection**; no built-in secrets/PII rule library (aiaudit offers user-defined regexes only, all four gates off by default); no disk projection of approved pages; no memory timeline view
- Warden is not a memory system; it is an MCP-only copilot (ADR-0047). "Replacing the foundation" would mean rewriting its entire memory contract (the `repotory_context` / `wiki_search` panels would be voided)

## Decision

1. **Do not replace the foundation.** Cinder keeps its single SQLite (FTS5 + sqlite-vec, zero CGO), its MCP tool surface, the human approval gate (ADR-0015), the zero-model capture path, and the frozen identifiers (ADR-0049). Warden's MCP contract is untouched.
2. **Absorb selectively**, with "fewer human corrections" as the experience north star (sdebench shows this, not the solve rate, is the experience metric of a memory system). Every absorption is evaluated against the gap inventory and must not break three load-bearing boundaries: **the human approval gate** (LLM output still lands only in pending), **privacy authorization** (new model endpoints off by default, per ADR-0012), and **zero-CGO single-file distribution**.
3. **The first action is measurement, not code**: build an evaluation set on the real note library using the existing abeval/queryset infrastructure, measure the retrieval gap, then decide the absorption order. "How big is the gap" currently has only the other side's benchmark, no number on our own data.
4. **Candidate absorptions** (inventory and suggested priorities in the research note; **none are scheduled yet**, each to be settled separately): session-start injection (SessionStart hook / managed-block upgrade), an `install all` one-command wiring CLI, a built-in secrets/PII rule library, read-only disk projection of approved pages, a rerank model (`hs-rerank-1`, MIT, 114M, is a candidate via an optional local endpoint), temporal retrieval, observations-style evidence revision (in pending + human-review form), and small-model triage (against the 40% rejection rate and compile cost).
5. **Explicitly not absorbed**: disposition traits (conversational persona, irrelevant to coding memory), the cloud / multi-tenant / Oracle / Prometheus enterprise operations surface, and the Postgres storage shape.

## Rejected routes

- **B — full replacement** (swap Cinder's foundation for a Hindsight server, re-point Warden's MCP): the approval gate, zero-model capture, single SQLite and the git-statistics tool surface are all lost or rewritten; Warden's three-panel contract is voided; Postgres + Python + an LLM call on every write are introduced; the product promises of 64 ADRs are overturned. **This amounts to abandoning Cinder as a product** — unavailable for as long as Cinder is maintained as an outward-facing product.
- **C — hybrid dual store** (Hindsight as a side retrieval lane, approved pages synced via retain): two-store consistency, sync drift, double the operations — the heaviest shape for a solo maintainer, with an LLM extraction cost on every sync. Pure surplus complexity once single-store reinforcement suffices.

## Consequences and reversal triggers

- Cost: solo engineering time spent item by item; rerank / small-model integration introduces an **optional** external endpoint dependency (off by default to hold the privacy authorization); the evaluation set needs ongoing maintenance, otherwise absorption gains cannot be proven.
- **Trigger to reverse toward B**: the self-built evaluation proves the gap unbridgeable **and** the owner decides Cinder is no longer maintained as a product.
- **Trigger to reverse toward C**: an external requirement appears that "must sell the Hindsight ecosystem (60+ integrations) as a feature".
- Competitive watch line: `hindsight-coding-agents` is expanding its coverage (22 harnesses) and zero-config ingestion fast. Cinder's differentiation moat is **the human approval gate + the local single file + the zero-model path**; any absorption that dilutes these three walks into the opponent's home ground.
